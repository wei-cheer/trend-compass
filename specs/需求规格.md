# 需求规格（我的复刻版）

> 状态：草案 · 最后更新：2026-11-24 · 来源：codefather「1. 需求分析」+ 我的定制

**项目代号**：`trend-compass`（热点罗盘）。项目名、接口名、目录结构均独立设计，不沿用成品仓库 `yupi-hot-monitor`。

## 一页结论

做一个**可复用的多热点聚合监控平台**：我先用来跟进《率土之滨》官方更新热点，产出视频和公众号文章；同时聚合其他游戏和圈外热点，让内容不单薄。平台也能给做自媒体的朋友复用。

## 需求规格表

| 维度 | 我的答案 | 来源 |
| --- | --- | --- |
| 目标用户 | 我自己（率土之滨游戏博主，需要跟进官方更新热点并创作视频、公众号发文）；以及和我一样做自媒体、需要复用该平台的朋友 | 我定制 |
| 核心价值 | 自动化**聚合多种热点**（官方更新 + 其他游戏 + 圈外热点），减少人工搜索时间 | 我定制（把“热点发现”扩展为“多热点聚合”） |

| 技术可行性 | 利用公开 API + 爬虫 + AI 分析，完全可行 | 示范答案 |

## 功能点

1. 用户手动输入要监控的关键词；相关内容真的出现时（用 AI 识别假内容），第一时间通知
2. 每隔一段时间自动搜集指定范围（比如《率土之滨》官方更新、其他游戏、圈外热点）内的热点，并且让用户能看到
3. 产品形态：响应式兼容的 Web 页面 + 封装成 Agent Skills 技能包，交给其他 AI 调用

## 为什么适合敏捷开发

需求明确且轻量：是一个工具类产品，不是复杂的企业级系统。
