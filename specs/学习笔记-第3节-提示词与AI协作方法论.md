## 一、先记住一句话（本节主线）

> **你不需要懂设计，只需要会表达需求。** 通过精准的提示词 + 合适的技能包，AI 就能产出专业级前端。

这节的三个方法都围绕这句话展开：提示词是"怎么说"，Git 是"说错了怎么退"，记忆提示词是"换了 AI 怎么接上"。

## 三、逐条讲透

### 1. "AI 味"是什么，怎么消

**AI 味**：大模型训练时看了大量同类设计，形成了"默认审美"——蓝紫渐变背景、圆角卡片、通用图标。你看到的很多 AI 网页都长一个样，这就是 AI 味。

教程给四种消除方法：

| 方法 | 做法 | 依赖 |
| --- | --- | --- |
| 指定色彩方案 | 不让 AI 自由发挥，明确告诉它用什么颜色 | 无 |
| 用特定 UI 库 | 比如 Aceternity UI，有独特视觉风格 | 装依赖 |
| 注入情感和场景 | 告诉 AI 产品调性（科技感 / 极客风 / 三国水墨） | 无 |
| 用前端美化技能 | 让 AI 参考专业 UI/UX 设计规范 | 需要 skill（如 ui-ux-pro-max，我们没有） |

**Aceternity UI 组件举例**（教程原表）：

| 组件 | 效果 | 适用场景 |
| --- | --- | --- |
| Meteors（流星） | 页面背景流星雨 | 首页、装饰性背景 |
| Sparkles（闪光粒子） | 文字或区域闪烁 | 标题强调、品牌标识 |
| Spotlight（聚光灯） | 鼠标跟随光影 | 卡片 hover、交互反馈 |
| Aurora Background（极光背景） | 流动的极光渐变 | 首屏背景 |
| Beams（光束） | 光束交叉效果 | 装饰性背景 |

> 对我们的实际判断：这节教程用了 Tailwind CSS 4 + Aceternity UI + Lucide 图标 + Context7 MCP。我们的项目是纯 CSS、没装这些。**先学方法，等接了真实数据再决定要不要引入**——一个只有探针状态的页面不值得上流星特效。

### 2. 提示词四技巧（本节最值钱的部分）

教程给的**完整示范提示词**（原文照录，可直接复用）：

```markdown
目前的界面风格过于死板（蓝紫配色 + 传统布局），请你在保持功能易用的前提下，帮我优化前端页面。

你需要利用前端美化技能（ui ux pro max）进行设计开发，并且必须采用 Aceternity UI 组件库（通过 Context7 插件来获取最新用法），来增强网站的科技感，但是注意不要过于花里胡哨、影响了页面的正常加载或使用。

我自己是一位 AI 编程博主，追求简洁高效、直观炫酷、充满科技感的页面，我急切地想要发现热点，想要第一时间给大家分享有价值的内容，你需要感受我的情绪，让前端页面体现出来。
```

**逐句对照四个技巧**（这就是"代码/文本与知识点对齐"）：

| 原文片段 | 对应技巧 | 拆开看它在干什么 |
| --- | --- | --- |
| "过于死板（蓝紫配色 + 传统布局）" | ① 指出问题 | 让 AI 明确知道当前状态哪里不满意，别让它猜 |
| "在保持功能易用的前提下" | ② 保持底线 | 强调不能为了好看牺牲可用性 |
| "利用前端美化技能…必须采用 Aceternity UI…Context7" | ③ 指定工具 | 明确告诉 AI 用什么来实现，别让它自由选型 |
| "我急切地想要发现热点…感受我的情绪" | ④ 注入情感 | 高级技巧，通过情绪描述让 AI 理解产品调性 |

**按我们的项目改写的示范答案**（换个功能做样例，避免直接抄教程）：

```markdown
目前的页面只有一个"探针状态：online"，样式过于单薄，请你在保持
"状态一眼可见"这个前提下，帮我优化 trend-compass 的前端展示。

你现在不要引入新的 UI 组件库，用现有的 CSS 完成，避免增加构建负担；
页面要能在 5173 正常加载，不能因为视觉效果拖慢首屏。

我自己是一位率土之滨的游戏博主，需要快速从一堆热点里挑出能做视频的选题，
我希望页面像一个作战沙盘：信息分区清楚、重点突出、我扫一眼就知道今天
该做哪条内容。你需要把这个"快速决策"的感觉做出来。
```

对照四技巧：① "过于单薄"=指出问题；② "状态一眼可见"=保持底线；③ "不要引入 UI 库，用现有 CSS"=指定工具（这里是反向指定）；④ "像作战沙盘、快速决策"=注入情感场景。

### 3. Git 后悔药（改坏了怎么退）

教程的做法：先 `git commit` 留一个干净节点，AI 改坏了就退回去重做。

**完整操作步骤（手指级，在 Git Bash 里做）**：

```bash
# 第 1 步：改之前确认当前是干净的（没有未提交改动）
cd /i/apps/trend-compass
git status          # 看到 "working tree clean" 才安全

# 第 2 步：确认回退点存在
git log --oneline -3    # 记下要退回的那条 commit 号，比如 3ea0c58

# 第 3 步：AI 改坏后，丢弃所有未提交的改动
git checkout .      # 只看工作区被改的文件；看到 "working tree clean" 就对了

# 第 4 步：如果 AI 已经提交了错误的 commit（比 checkout 更进一步）
git reset --hard 3ea0c58    # ⚠️ 会丢掉这条之后的全部提交，用前先确认commit号
```

**看到什么算对**：`git checkout .` 之后 `git status` 显示 `working tree clean`，页面恢复到上一次提交的样子。

**失败长什么样**：如果 `git status` 还有 `?? 新文件`，`git checkout .` 不会删未跟踪的新文件——要手动删，或 `git clean -fd`（⚠️ 会删所有未跟踪文件，先看清列表）。

**教程强调的最佳实践**：AI 编程中"改着改着就改坏了"很常见，所以**每次改动前先有个 commit 当锚点**。我们项目每 Step 一条 commit、红绿阶段分开提交，正好是这套实践的落实——这也是为什么前面反复强调"改完提交再验下一步"。

### 4. 中断了怎么恢复（AI 任务的四套方案）

教程给的方案表：

| 方案 | 说明 | 适用场景 |
| --- | --- | --- |
| 拆分任务 | 把大任务拆成多个小任务，分步完成 | 改动范围大（如全站 UI 重构） |
| 换模型 | 切换到更稳定的大模型 | 特定模型频繁断连 |
| 新开对话 | 重新开一个对话窗口 | 上下文过长导致中断 |
| 提供记忆 | 通过提示词帮 AI 找回之前的工作记忆 | 新对话中继续之前的任务 |

**中断的三个原因**：网络不稳定 / 上下文过长（对话历史超出窗口）/ 任务过大（一次改的代码太多）。

**教程给的记忆恢复提示词**（原文在页面只显示到开头，后面是"提供给你的资料"清单，此处照录可见部分）：

```markdown
你是一位专业的程序员，现在请你根据我的需求和方案、以及已经开发完成的前端和后端项目，在此基础上进行优化和功能扩展。

## 提供给你的资料
```

**我的补全版**（教程截断了，这是按我们项目实际补的，可直接用）：

```markdown
你是一位专业的程序员。请根据下面的资料，接着做 trend-compass 的 Step N。

## 提供给你的资料
1. 需求：specs/需求规格.md
2. 方案：specs/实施方案-最小可运行骨架.md
3. 当前进度：specs/开发路线说明.md（第 7 节进度锚点）
4. 本步任务：specs/任务说明-StepN-*.md
5. 已完成步骤的验收记录：specs/Step*-说明.md
6. 当前代码状态：git log --oneline -5 的输出 + git status 输出

## 你要做的
先读上面 1~5，确认当前状态；只做任务说明里写的事，不扩范围；
每步提交不推送；做完贴回验收输出。
```

> 这套正好解释了我们为什么每步都落 `StepN-说明.md` 和 `任务说明-StepN-*.md`——**文档本身就是给下一个 AI 的记忆包**。教程用"新开对话 + 记忆提示词"应急，我们把记忆提前固化成文件，效果一样但更可靠。

### 5. Skills + MCP 协作（了解即可）

教程把 Acertinity UI 改造拆成三方协作：**Skills 提供设计方向**（ui-ux-pro-max 告诉 AI 怎么选配色、排版、动效）→ **MCP 提供最新技术文档**（Context7 拿 Acertinity UI 最新用法）→ **AI 综合两者完成实际开发**。

我们当前是"方案 AI + 代码 AI"双 AI 模式（见 `开发路线说明.md`），Skills/MCP 是另一维度的工具分工，不冲突。等需要专业设计能力时可以考虑引入，现在用不上。

---

### 6. 优化前后对比（教程的成果，供参考）

教程做完美化后的五处改变：配色从蓝紫 → 深色科技感主题；加流星/光影动态效果；布局信息层次更清晰；加了 Lucide React 图标；卡片 hover + 过渡动画。

教程一句话点破 Tailwind CSS 4 的价值：它是"原子化"CSS 框架，把每个 CSS 属性封装成工具类（`bg-blue-500`、`text-lg`、`flex`），直接在 HTML 里组合，不用手写 CSS 文件——这种形式特别适合 AI 编程，因为 AI 可以直接在组件里加样式类，不用跨文件改。

## 六、落到我们项目上的结论

- **Step 5 就是美化（2026-11-25 决定，已偏离教程建议）**：教程建议等接了数据再美化，我们改为现在就把两行字的状态页做成三国水墨风——因为这是练「给 AI 下设计要求」的好时机，页面简单、改坏好回退。**接数据延后**。依据：`specs/设计规范-前端美化-三国水墨.md`。
- **现在就能用的**：git 后悔药（我们已经在用每步 commit）、记忆包（我们已经在写 Step 说明和任务说明）。
- **要装工具的（Aceternity UI / Tailwind / Context7 / ui-ux-pro-max）**：等真做美化时再评估，不提前引入。
